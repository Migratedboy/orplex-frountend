Architecture plan

Bringing Antigravity-style productivity to your agent network

A phased plan for adding a manager surface, browser-in-the-loop verification, artifacts, multi-agent collaboration, and a persistent knowledge base — mapped onto your existing Node/Express + Supabase + NVIDIA NIM stack.

Target architecture

Manager surface routes work → specialist agents execute in parallel → results become reviewable artifacts → successful patterns persist to the knowledge base and loop back in.

Phase 1

Manager surface + artifacts

The foundation everything else hangs off. Biggest trust win for the least effort.

  • Add a tasks table in Supabase: id, agent, status (queued/running/needs_review/done), plan, created_at. Created via POST /tasks; agents pick up work by polling or via Supabase realtime subscriptions.
  • Add an artifacts table: id, task_id, type (plan/diff/screenshot/recording), content_or_url. Store diffs as unified git-diff text, screenshots/recordings in a Supabase Storage bucket.
  • On the UI side, add a slide-out panel listing tasks as cards (status pill + artifact thumbnails). Clicking a node in the constellation UI opens that task's artifact trail instead of a raw log dump.
Phase 2

Browser-in-the-loop verification

The single highest-leverage feature — this is what actually gives you Antigravity-style confidence instead of "trust me, it compiles."

  • Add Playwright as a dependency. Wrap it as a tool the Code agent can call: launch_and_test(port) — starts the dev server via child_process, opens the page headless, grabs a screenshot, checks the console for errors, optionally records video, returns pass/fail + artifact paths.
  • If your NIM model doesn't support native function calling reliably, fall back to structured JSON output (respond only with {"tool": ..., "args": ...}) and parse it yourself.
  • Every test run becomes an artifact row automatically — "did this actually work" becomes something you can look at, not something you have to trust.
Phase 3

Multi-agent collaboration on one task

You already have separate specialist agents — this phase lets them work the same task instead of separate ones.

  • Manager decomposes an incoming task into subtasks, each tagged to a specialist agent, all pointing at the same task_id.
  • Instead of direct agent-to-agent messaging, have agents read/write to the shared task row in Supabase — Code writes a diff artifact, Browser agent tests it, Research agent checks docs if something fails. Loosely coupled, easy to debug, easy to extend.
Phase 4

Persistent knowledge base

  • A learnings table per project: successful patterns, gotchas, snippets. Doesn't need to be fancy — pgvector on Supabase for real similarity search, or keyword search to start.
  • Before a task kicks off, do a retrieval pass and inject relevant past learnings into the system prompt. This is what makes agent #50 on a project faster than agent #1.
Phase 5

Inline feedback on artifacts

  • A comments table linked to artifact_id. Leaving a comment appends it to that task's message history in Supabase and includes it in the agent's next NIM call — no restart needed.

Security, from day one

Given the prior NVIDIA key exposure, build this in rather than bolting it on later: treat anything the Research agent scrapes off the web as untrusted input — never let scraped page content get executed as instructions. Keep any shell/browser execution sandboxed in a restricted child process. The PromptArmor finding on Antigravity's own prompt-injection vulnerability is a direct preview of what happens if this step gets skipped.
