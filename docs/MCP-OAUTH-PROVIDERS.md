## Providers needing a vendor-registered client (no dynamic registration)

These providers' authorization servers do not support dynamic client
registration (RFC 7591), so the OAuth leg needs ONE app registered with the
vendor. Register `http://127.0.0.1:49431/callback` (desktop) and
`<app-origin>/api/mcp/oauth/callback` (hosted) as redirect URIs, then set:

- **Render** (render): `ORPLEX_MCP_CLIENT_ID_RENDER` (confidential clients also: `ORPLEX_MCP_CLIENT_SECRET_RENDER`)
- **Jira** (jira): `ORPLEX_MCP_CLIENT_ID_JIRA` (confidential clients also: `ORPLEX_MCP_CLIENT_SECRET_JIRA`)
- **Figma (official remote)** (figma-remote): `ORPLEX_MCP_CLIENT_ID_FIGMA_REMOTE` (confidential clients also: `ORPLEX_MCP_CLIENT_SECRET_FIGMA_REMOTE`)
- **Slack** (slack): `ORPLEX_MCP_CLIENT_ID_SLACK` (confidential clients also: `ORPLEX_MCP_CLIENT_SECRET_SLACK`)
- **ElevenLabs** (elevenlabs): `ORPLEX_MCP_CLIENT_ID_ELEVENLABS` (confidential clients also: `ORPLEX_MCP_CLIENT_SECRET_ELEVENLABS`)
- **OneDrive / SharePoint** (one-drive): `ORPLEX_MCP_CLIENT_ID_ONE_DRIVE` (confidential clients also: `ORPLEX_MCP_CLIENT_SECRET_ONE_DRIVE`)

The static-client lane is already wired: `mcp-catalog.ts` injects these env
values into the entry's `oauth` spec at load, and `oauth/provider.ts` +
`hub.ts` pass them through instead of attempting DCR.
